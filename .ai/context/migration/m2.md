# M2: the build zone's flow in the dispatcher (replaces stage 4's 4.4), PLAN (written 2026-11-21)

ADR-0063 narrows 4.4. The dispatcher runs only the phases that belong to the build zone. The picker, the review
panel, the verifier, acceptance and the shipper are not ported: the queue (M5) and the review zone (M6) replace them,
and until M6 the owner reviews with `/review` on the Mac (D3). Built in `profitbuild/factory` (`dispatcher/src/flow/`),
with incident-platform's adapter as the first product. Umbrella item: #0-287; one item per part (split on
2026-11-21), named at each part below.

**Before:** M1 (#0-278) merged and `factory` tagged `v0.1.0`; #0-280 (the gate's schema checked against
`run-tests.sh`) before the first gate answer is read: its way is `factory`'s own `checkGateAnswer` at that tag, run in
Lint Workflows on every answer of `test-run-tests.sh`'s cases (ADR-0061, amended; the item's Record).

## Parts, in order

### M2.0 The build agents move into `factory`'s plugin (ADR-0060 D5): #0-299
- **What:** `architect`, `implementer` and `implementer-light`, with the rules they read (`.ai/rules/implementation.md`'s
  factory part) and the settings the dispatcher passes (`settings/autopilot.json`), move into `factory`'s plugin.
  `factory` holds no agent definition yet (only `.claude/settings.json`, checked 2026-11-21). The copies in
  incident-platform are removed in the same change; the product keeps only its own rules, which the adapter names.
  The old path, still running until M4, loads them from `/opt/factory` too, so no second copy exists to drift
  (review round 1 of #0-286, ARC-02).
- **Where:** `factory` (`agents/`, `settings/`), incident-platform `.claude/agents/` (owner-only).
- **Check:** `git grep` finds each definition in one repository only, and an init event lists the plugin's agent.

### M2.1 Spike: one agent of the plugin as `claude -p`'s main thread: #0-300
- **What:** run `implementer` from `/opt/factory` in a task container as the main thread of `claude -p`. Try
  `--agent <name>` first; else the definition's body as `--append-system-prompt-file` with its tools and model from
  the frontmatter. Then settle:
  - whether the plugin's hooks run in that mode (they stay a second layer until M7);
  - what replaces ADR-0058's isolation probe. Proposal: the `stream-json` init event's agent, tools and
    `plugin_errors`.
- **Where:** the VM, one trial task. **Check:** the recorded init event of one call, in this file's Record.

### M2.2 One agent call: #0-301 (with M2.3)
- **What:** `docker exec <task> claude -p --plugin-dir /opt/factory --output-format stream-json --verbose
  --json-schema <schema> --permission-mode dontAsk --settings /opt/factory/settings/autopilot.json --max-turns <n>
  "<prompt>"`.
  - stdout goes to `tasks/<runId>/calls/<n>-<agent>.jsonl`, and the answer is `structured_output`;
  - no answer is a stop (`as()`);
  - an init event with `plugin_errors`, or not the expected agent and tools, stops the run.
- **Where:** `factory`, `dispatcher/src/flow/agent-call.mjs`. **Check:** `node:test` with an injected `runAgent`
  and recorded `stream-json` fixtures.

### M2.3 The phases of the build zone: #0-301
- **What:**
  - plan (`architect`);
  - implement (`implementer` or `implementer-light` by Complexity);
  - the path gate (`changed-paths` from the base's blobs, in the container, #0-278);
  - the test gate (`run-tests.sh` by `docker exec`), with up to `MAX_TEST_FIXES` 2 fix calls.

  Both gates are the product's commands, run through `factory`'s `src/product/commands.mjs` (`factory` PR #20).
  It unpacks the base's `trustedPaths` into a fresh directory in the container and runs the adapter's script from
  there. It has no caller yet, and this part is its first.
  - **fix-review**: the implementer given findings by id, which the owner's `/review` produces until M6 and
    review-app after it.

  Kept: `stopItem` and the limits (`MAX_ROUNDS` 3, `MAX_AGENT_CALLS` 45, the breaker), and `notify.sh`'s events.

  Not ported: preflight's bot checks, pick, review rounds, verify, acceptance, ship.
- **Where:** `factory`, `dispatcher/src/flow/`.
- **Check:** whole runs against a fake agent: each stop reaches `stopItem` with its stage, ported from
  `test-autopilot-workflow.mjs`.

### M2.4 The dispatcher commits: #0-302 (folds in #0-212)
- **What:** agents do not commit. After each call that changed the tree, the dispatcher runs, in the task's
  container with its own git flags, `git add -A` and a commit. The message comes from the answer, with the trailers
  `Factory-Run` and `Factory-Agent` (#0-212) and, from M5, `Task:` and `Feature:`. The commit is read back as a
  bundle into the task's own repository under `$FACTORY_STATE_DIR` (alternates onto `FACTORY_REPO_DIR`, config held
  as the push repository's). Each commit must be exactly one, with the recorded head as its only parent.
- **Where:** `factory`. **Check:** a planted second commit, a merge, or a missing trailer is refused.

### M2.5 Per task, not per dispatcher (ADR-0063 G1, ready for two slots in M5): #0-303
- **What:**
  - a lock per task instead of the one `flock` (ADR-0060 D7 as amended);
  - the sweep removes only what carries the task's `runId` label, and a separate sweep removes orphans (a run with
    no live lease);
  - the Maven cache per slot (`factory-dispatcher-m2-<slot>`), or a shared read-only cache with a per-task layer;
  - `state.json` written atomically under a short state lock;
  - the slot count is configuration (`FACTORY_SLOTS`), 1 in M2.
- **Where:** `factory`, `dispatcher/src/state/`, `container/`.
- **Check:** two fake tasks in one process do not remove each other's resources, and the breaker counts both.

### M2.6 Carried from 4.3a–c: #0-304, with #0-284, #0-249 and #0-283
- **What:**
  - a BLOCKED reason never carries GitHub's text into a PR;
  - resume by `runId`, and a new task refused while one is `running` on the same item;
  - `blockTask` counts the block in `state.json`;
  - a mint retried after a timeout revokes what it can find;
  - #0-284 (the task container checked fully before `postCreate`/`postStart` run);
  - #0-249 and #0-283 (Claude Code pinned in the image, `dev`'s sudo rule for `init-firewall.sh` held to its
    arguments).
- **Where:** `factory`, incident-platform `.devcontainer/` (owner-only).
