# M2: the build zone's flow in the dispatcher (replaces stage 4's 4.4), PLAN (written 2026-11-21)

ADR-0063 narrows 4.4. The dispatcher runs only the phases that belong to the build zone. The picker, the review
panel, the verifier, acceptance and the shipper are not ported: the queue (M5) and the review zone (M6) replace them,
and until M6 the owner reviews with `/review` on the Mac (D3). Built in `profitbuild/factory` (`dispatcher/src/flow/`),
with incident-platform's adapter as the first product. Umbrella item: #0-287; one item per part (split on
2026-11-21), named at each part below.

**Before:** M1 (#0-278) merged and `factory` tagged `v0.1.0`; #0-280 (the gate's schema checked against
`run-tests.sh`) before the first gate answer is read: its way is `factory`'s own `checkGateAnswer` at that tag, run in
Lint Workflows on every answer of `test-run-tests.sh`'s cases (ADR-0061, amended; the item's Record).

### M2.2 One agent call: #0-301 (with M2.3)
- **What:** `docker exec <task ID> /usr/bin/timeout … /usr/bin/env -i <the closed list> /usr/local/bin/claude -p --plugin-dir /opt/factory --agent
  factory:<agent> --restricted --tools <the agent's frontmatter tools> --add-dir /workspace --output-format
  stream-json --verbose --json-schema <schema> --permission-mode dontAsk --max-turns <n>`, `cwd` `/workspace`, the
  prompt on stdin. This is ADR-0064's F3 (2026-11-21, #0-300, point 2 as amended by the spike):
  - **The permission rules** a task's agents need live in the factory's managed settings, which this part (#0-301)
    writes in `factory` and mounts read-only on the task container's `/etc/claude-code`. The mount goes into the
    exact mount comparison and #0-284's `HostConfig` table too. No `settings/autopilot.json` passed by `--settings`:
    under `allowManagedPermissionRulesOnly` its rules would be ignored. No earlier part writes them (review round 1
    of #0-299's plan).
  - **The environment** is `env -i` with a closed list of literals, which carries the accepted `containerEnv` and
    `DISABLE_AUTOUPDATER=1` and `DISABLE_UPDATES=1` (ADR-0064 point 5, ADR-0065),
    `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` (point 5 as amended on the review of opencomputer, in #0-301's code),
    `ANTHROPIC_BASE_URL` (the proxy's address, M2.7; the token is not in the list), with `PATH` the system
    directories. The managed settings also hold `strictKnownMarketplaces: []`, and
    the init event's `plugins` must be the factory's and, besides it, exactly Claude Code's built-in plugins of the
    closed list (ADR-0064 point 3 as amended for #0-301).
  - **A container lives one run** (one `cli.mjs run` invocation): a resume always makes a new one, and review fixes
    are a new run (ADR-0064's Consequences).
    - Code a call ran can change a later call of the same run.
    - Across runs it reaches through `~/.m2` and the image store (ADR-0062, #0-285).
    - The boundaries against it are outside the container (commit check, PR's CI, review, push), not the gates
      inside it.
    - The `env -i` literals are not secret.
  - **The form is F3** (ADR-0064 point 2 as amended by M2.1's spike): `--restricted`, `--tools` built from the
    agent's frontmatter `tools`, `--add-dir /workspace` with `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` in the
    `env -i` list, `cwd` `/workspace`, and the prompt on stdin (`--tools` takes several values).
  - **The agent** is named by the plugin's name, `--agent factory:<agent>` (M2.0).
  - stdout goes to `tasks/<runId>/calls/<n>-<agent>.jsonl`, and the answer is `structured_output`;
  - no answer is a stop (`as()`);
  - the init event is checked whole before the answer (ADR-0064 point 3): `plugin_errors`, or not the expected
    agent (the factory's, the built-in ones equal to a second closed list), plugin (the factory's, the built-in ones
    equal to the closed list), tools, model, permission mode or Claude Code version, or a non-empty `mcp_servers`,
    stops the run; from #0-313 on, an `apiKeySource` other than
    `"apiKeyHelper"` too.
    Under F3 the expected `tools` are exactly the `--tools` list, Grep and Glob next to Bash (the spike's D2), and
    `StructuredOutput`, which each agent's frontmatter names: `--agent` trims the tools to the frontmatter, and the
    answer comes back through that tool (the Record's measurement of 2026-11-22). M2.0's
    measurement 2 (Bash drops Grep and Glob) holds for a call without `--tools`. A version bump re-records them
    (#0-249, #0-283).
- **Decided 2026-11-22** (`/research` of #0-301, the owner's K2 and g1; ADR-0064 points 3 and 5 amended):
  - **no Claude key in the container** (K2): the call reaches Claude through the proxy of M2.7 (#0-313).

  - **on the review of the factory's plan** (2026-11-22): the built-in plugins as a closed list of names beside the

  - modes are seen (`--raw`: gitlinks refused, and symlinks for scoped agents);
  - `commitMessage`'s shape is in its answer schema, and the trailers are parsed back as exactly the dispatcher's;
  - the dispatcher's git runs with `env -i` and no hooks, fsmonitor or signing; a filter's drift is held by CI;
  - a call with no change makes no commit;
  - one bot identity;
  - the schema refuses unknown agents;

    new container's work directory by ADR-0062 point 2's helper from a bundle of it (lifting #0-301's refusal);
  - the push stays #0-276's: a fresh push repository filled from the lasting one.
- **What:** agents do not commit. After each call that changed the tree, the dispatcher runs, in the task's
  container with its own git flags, `git add -A` and a commit. The message comes from the answer, with the trailers
  `Factory-Run` and `Factory-Agent` (#0-212) and, from M5, `Task:` and `Feature:`. The commit is read back as a
  bundle into the task's own repository under `$FACTORY_STATE_DIR` (alternates onto `FACTORY_REPO_DIR`, config held
  as the push repository's). Each commit must be exactly one, with the recorded head as its only parent.
- **Each agent's write scope, the dispatcher's** (the owner's option (b), review rounds 1 and 2 of #0-299's plan):
  - the paths a call's commit changed (`git diff-tree -r --no-renames`, amended by the decisions to `-r -z --raw`, so a move into the scope shows both of its
    paths, in the task's repository with the dispatcher's git) are held to that agent's scope, through the one path
    matcher `checkChangedPaths` (`src/product/trusted-paths.mjs`, `factory` PR #20) that M3.1 extends too, never a

    adapter;

  - a path outside the scope stops the task. This replaces the architect's `write-scope.sh`, which the plugin does
    not carry (M2.0);
  - until M4 the architect's scope is written in four places (its old frontmatter, both settings files, the
    adapter), and nothing compares the adapter's with the others: accepted, since the old path's three are frozen

### M2.5 Per task, not per dispatcher (ADR-0063 G1, ready for two slots in M5): #0-303
- **Decided 2026-11-21** (`/research` of #0-303 with #0-309, the owner's option B): only what holds whatever the
  daemon's model is goes here; the sweep's scope, the orphans, the Maven cache and #0-309 go to M3.4 (#0-285), which
  chooses that model (a shared daemon, a user per slot, or Sysbox's daemon in the task container, ADR-0063 G1-b) and
  under which most of a label-scoped sweep would be thrown away. Why: on a shared daemon a label is no boundary (a
  task's code holds the socket and makes objects unlabelled, or labelled as another run's: Testcontainers' and
  compose's are unlabelled anyway), so no sweep can tell a live task's unlabelled objects from a killed run's, and
  until M4 the whole-daemon sweep is what keeps the rollback's credential volumes off the daemon (ADR-0062 point 5).
- **What:**
  - a lock per task, `tasks/<runId>/lock`, by `lock.mjs`'s own `flock` on a descriptor the run holds (ADR-0060 D7
    as amended for #0-303); the dispatcher's one lock stays only for `cli.mjs sweep` and the moment a run takes its
    slot (and, with #0-303's code, its end's sweep: ADR-0060 D7 as amended with the code);
  - a task is live while its lock cannot be taken (`flock --nonblock`): no pid, no timeout, released by the kernel
    when the run dies; this stands in for M5's lease until the Project holds it;
  - a short state lock around each read, change and write of `state.json` and the task records (the writes stay
    `writeJsonAtomic`'s);
  - the slot count is configuration (`FACTORY_SLOTS`, 1 until M5): a run is refused while as many tasks are live;
  - the sweep of the whole daemon (ADR-0062 point 7) runs at a run's start and end only while no other task is
    live, which in M2 is always; otherwise a run removes only what carries its label (`removeOwnObjects`), and
    nothing of a live task's (ADR-0062 point 7 as amended for #0-303). The order holds that: a run takes its own
    task lock first, then checks the others' liveness and sweeps at its start under the dispatcher's lock, and
    checks again and sweeps at its end under that lock too, before it releases its task lock. **Order superseded by
    #0-303's code:** the slot section counts the live tasks and checks the daemon before the run's own task lock, and
    a run's end that cannot take the dispatcher's lock removes its own objects (ADR-0062 point 7, "Amended with
    #0-303's code"; the Record below);
  - `cli.mjs sweep` refuses while any task's lock is held, naming that task's `runId`, and `--force` does not
    override it (`--force` is for a container a killed run left labelled as the rollback's, not for a live task) (review
    round 1 of #0-303's decisions: the dispatcher's lock no longer spans a run, so it alone no longer keeps the two
    apart).
- **Moved to M3.4 (#0-285):** the orphans' sweep, the sweep's scope on a shared daemon, the Maven cache (per slot, or
  a shared read-only cache with a per-task layer, e.g. Maven 3.9's `maven.repo.local.tail`, to check on 3.9.16), and
  #0-309 (volumes removed without their names in argv).
- **Where:** `factory`, `dispatcher/src/state/`, `container/`.
- **Check:** a second run is refused while one is live and `FACTORY_SLOTS` is 1; a run does not sweep the daemon
  while another task is live, and sweeps it whole when none is; `cli.mjs sweep` and `sweep --force` refuse while a
  task's lock is held; a killed run's lock is free again, a child process of it still alive included (the lock's
  descriptor is `O_CLOEXEC`); two concurrent writes of `state.json` lose neither, and the breaker counts both.
