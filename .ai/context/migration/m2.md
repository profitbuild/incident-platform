# M2: the build zone's flow in the dispatcher (replaces stage 4's 4.4), PLAN (written 2026-11-21)

ADR-0063 narrows 4.4. The dispatcher runs only the phases that belong to the build zone. The picker, the review
panel, the verifier, acceptance and the shipper are not ported: the queue (M5) and the review zone (M6) replace them,
and until M6 the owner reviews with `/review` on the Mac (D3). Built in `profitbuild/factory` (`dispatcher/src/flow/`),
with incident-platform's adapter as the first product. Umbrella item: #0-287; one item per part (split on
2026-11-21), named at each part below.

**Before:** M1 (#0-278) merged and `factory` tagged `v0.1.0`; #0-280 (the gate's schema checked against
`run-tests.sh`) before the first gate answer is read: its way is `factory`'s own `checkGateAnswer` at that tag, run in
Lint Workflows on every answer of `test-run-tests.sh`'s cases (ADR-0061, amended; the item's Record).

## Parts, in order

### M2.0 The build agents, product-neutral, in `factory`'s plugin (ADR-0060 D5 as amended): #0-299
Decided with the owner on 2026-11-21 (`/research` of #0-299, option C and the way (a) of product knowledge). Why not a
move of the three files, as this part first said: their text names incident-platform's paths and rules (ADR-0055 lists
that as a violation); the old path, still running until M4, resolves them in the product's `.claude/agents/` and runs
in a devcontainer that has no `/opt/factory`; and Claude Code ignores a plugin agent's frontmatter `hooks:`.
- **`factory` (one PR, written with `profitbuild-factory-dev`):**
  - a plugin: `.claude-plugin/plugin.json`, `agents/architect.md`, `agents/implementer.md`,
    `agents/implementer-light.md`, written product-neutral. Their modes stay (`implement`, `fix-tests`, `fix-review`,
    `fix-acceptance`, `self-check`; the architect's plan and ADR), minus the commit, which is the dispatcher's (M2.4);
  - **product knowledge, way (a):** the agent's text starts by reading the product's `CLAUDE.md` (`/workspace/CLAUDE.md`,
    with Read, so the way holds whether or not Claude Code loads it by itself in a `-p --agent` session, which M2.1
    finds out), and the agent reads what it points to for its task (incident-platform: `.ai/README.md`'s map, `.ai/rules/`,
    `.ai/context/`, `.ai/decisions/`); the paths of the task's own files (plan, handoff, gate log) come in the task
    from the dispatcher. No adapter field: one comes only when a product needs another entry point. `@`-imports only
    for short text every task needs;
  - `hooks/hooks.json` with `foreground-bash` (the turn budget, #0-206), through `${CLAUDE_PLUGIN_ROOT}`. The
    architect's boundary hooks (`readonly-bash`, `write-scope`) are not ported: its write scope becomes the
    dispatcher's own check of the paths each call's commit changed (M2.4, #0-302; ADR-0063 as amended for #0-299),
    outside the container, so a branch cannot turn it off as it could a hook in the container (`disableAllHooks` in
    the clone's settings), and it sees a tracked file written through Bash too (review round 1 of #0-299's plan,
    the owner's option (b)). What it does not see, a file `git add -A` leaves out (an ignored path, `.git/`, one
    hidden by `.git/info/exclude` or `skip-worktree`), stays in the container for the next call and the gate: the
    architect loses its least privilege inside the task, not the task's boundary, which the same task's implementer
    has never had either (review round 2);
  - a test: no product path or name in `agents/` (a list of refused patterns), and no `hooks:` in an agent's
    frontmatter, since it would be ignored; `claude plugin validate` in `factory`'s CI if it runs offline, without a
    token.
- **incident-platform (owner-only):** `CLAUDE.md` gains what the agents' text carries today about this product, for
  the factory's agents: where a plan lives (`.ai/work/<item>/`), where an ADR goes, which rule files to read, through
  the existing pointers to `.ai/README.md`; and its "AI factory" line that sends an autopilot agent to its own
  definition in `.claude/agents/` names the plugin's agents too, so they are not pointed at the old path's copies.
- **The `spring-boot` profile** (Maven and `-am`, Testcontainers) stays in the product's rules
  (`.ai/rules/implementation.md`) while there is one product; it moves to `factory` with the review rules' profile in
  M6.1 (#0-294).
- **The old path:** `.claude/agents/architect.md`, `implementer.md`, `implementer-light.md` stay here unchanged until
  M4, the old path's own, frozen; #0-290 removes them. One definition per agent from M4 on.
- **The dispatcher calls the plugin's name**, `--agent factory:implementer`: a plugin agent is namespaced, and in the
  container the clone's `.claude/agents/implementer.md` (until M4) has the higher priority under its bare name.
- **What the knowledge's source is not:** everything the agent reads from `/workspace` is its own working tree, which
  its branch can change; it is the agent's context, never a ground for the dispatcher's decisions (ADR-0060 D6).
- **Check:** the test above passes in `factory`; a `claude --plugin-dir` session lists `factory:architect`,
  `factory:implementer` and `factory:implementer-light`; `CLAUDE.md` names what the agents read; the old path's tests (`test-autopilot-workflow.mjs`,
  `check-hook-entries.rb`, `check-agent-commands.rb`) still pass, untouched.

### M2.2 One agent call: #0-301 (with M2.3)
- **What:** `docker exec <task> claude -p --plugin-dir /opt/factory --output-format stream-json --verbose
  --json-schema <schema> --permission-mode dontAsk --settings /opt/factory/settings/autopilot.json --max-turns <n>
  "<prompt>"`. `settings/autopilot.json` is created in `factory` by this part (#0-301), from what M2.1 found: the
  permission mode, the allow rules a task's agents need, and the flags that keep the clone's `.claude/settings.json`
  out of the session. No earlier part writes it (review round 1 of #0-299's plan). The agent is named by the
  plugin's name, `--agent factory:<agent>` (M2.0), in the form M2.1 settles.
  - stdout goes to `tasks/<runId>/calls/<n>-<agent>.jsonl`, and the answer is `structured_output`;
  - no answer is a stop (`as()`);
  - an init event with `plugin_errors`, or not the expected agent and tools, stops the run.
- **Where:** `factory`, `dispatcher/src/flow/agent-call.mjs`. **Check:** `node:test` with an injected `runAgent`
  and recorded `stream-json` fixtures.

### M2.3 The phases of the build zone: #0-301
- **What:**

  - the path gate (`changed-paths` from the base's blobs, in the container, #0-278);

  Not ported: preflight's bot checks, pick, review rounds, verify, acceptance, ship.
- **Where:** `factory`, `dispatcher/src/flow/`.
- **Check:** whole runs against a fake agent: each stop reaches `stopItem` with its stage, ported from
  `test-autopilot-workflow.mjs`.

### M2.4 The dispatcher commits: #0-302 (folds in #0-212)
- **What:** agents do not commit. After each call that changed the tree, the dispatcher runs, in the task's
  container with its own git flags, `git add -A` and a commit. The message comes from the answer, with the trailers
  `Factory-Run` and `Factory-Agent` (#0-212) and, from M5, `Task:` and `Feature:`. The commit is read back as a
  bundle into the task's own repository under `$FACTORY_STATE_DIR` (alternates onto `FACTORY_REPO_DIR`, config held
  as the push repository's). Each commit must be exactly one, with the recorded head as its only parent.
- **Each agent's write scope, the dispatcher's** (the owner's option (b), review rounds 1 and 2 of #0-299's plan):
  - the paths a call's commit changed (`git diff-tree -r --no-renames`, so a move into the scope shows both of its
    paths, in the task's repository with the dispatcher's git) are held to that agent's scope, through the one path
    matcher `checkChangedPaths` (`src/product/trusted-paths.mjs`, `factory` PR #20) that M3.1 extends too, never a
    second one;
  - the scope comes from the product's adapter, a new field `writeScopes`, keyed by the agent's bare name (the
    plugin's prefix is the factory's, the adapter is the product's), e.g. `{"architect": [".ai/decisions/",
    ".ai/work/"], "implementer": ["*"], "implementer-light": ["*"]}`, in `factory`'s schema and incident-platform's
    adapter;
  - **fail closed:** the dispatcher refuses to call an agent with no entry, and an unlimited one says so (`["*"]`),
    as the old path's `check-hook-entries.rb` refuses an agent with tools and no guard unless `UNGUARDED` names it;
  - a path outside the scope stops the task. This replaces the architect's `write-scope.sh`, which the plugin does
    not carry (M2.0);
  - until M4 the architect's scope is written in four places (its old frontmatter, both settings files, the
    adapter), and nothing compares the adapter's with the others: accepted, since the old path's three are frozen
    and go at M4 (#0-290).
- **Where:** `factory` (dispatcher, `schemas/adapter.schema.json`), incident-platform `.factory/adapter.json`
  (owner-only). **Check:** a planted second commit, a merge, or a missing trailer is refused; an architect's commit
  that changes a path outside its scope stops the task, one inside passes (tests).
