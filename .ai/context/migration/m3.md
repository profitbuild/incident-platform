# M3: push, PR, trace and the credential proxy (replaces stage 4's 4.5–4.7), PLAN (written 2026-11-21)

The dispatcher publishes M2's branch as builder-app and holds Claude's key behind a proxy. One PR opened by it and
merged by the owner exits the step (ADR-0063 D5). There is no switch between two paths: the old path stays runnable
until M4 removes it, but the owner starts only one at a time. Umbrella item: #0-288; one item per part (split on
2026-11-21), named at each part below.

**Before:** M2's exit. The plugin's implementer runs without the old path's `guard-tests` and `guard-migrations`
hooks (#0-299), and that leaves no gap here: the required `Factory guards` check (`check-factory-guards.sh`, backlog #0-113) already holds every pull request,
the dispatcher's too: rule 1 a deleted test or a new `@Disabled`, rule 2 fewer assertions in an existing test, rule 4
an edited migration that is on the base; it passes only the owner's own pull request or one whose head the owner
approved (review round 3 of #0-299's plan).

## Parts, in order

### M3.1 Checks before a push (ADR-0060 D7), outside the container: #0-305 (with M3.2)
- **What:** these run in the push repository after the task's bundle is read into it, never in the task's clone.
  They build on `factory` PR #20:
  - `withTaskObjects` (`src/git/task-objects.mjs`) is the repository made from the task's bundle, the push's own;
  - `checkChangedPaths` (`src/product/trusted-paths.mjs`) already refuses a changed `trustedPaths` entry against
    the base's adapter, and is the one function these checks extend.

  The checks:
  - the branch's commits are exactly M2's recorded chain, and each `Factory-Agent` is its call's agent;
  - `merge-base` is the recorded base, and there are no merges;
  - `changed-paths` from `main`, by the dispatcher's own parser of `protectedPaths` (tested against a copy of
    `.ai/rules/protected-paths.md`'s lists, held equal by `check-factory-copies.rb`: #0-278 AC11's second half): an
    Owner-only path stops the task, `needsHuman` sets the owner's label, and no
    `trustedPaths` entry changed;
  - every commit carries the run's trailers.

  For a rebase task (M5, ADR-0063 G1-a) the check is "the base is current `main`" and the push is `--force-with-lease`
  to `factory/**` only. The code path is written here, used from M5.
- **Where:** `factory`. **Check:** each planted case is refused: a merge, a protected path, a missing trailer, a
  base that is not `main` on a rebase.

### M3.2 Push and PR: #0-305
- **What:**
  - `git push` as builder-app;
  - `GET /pulls?head=` first, then `POST` or `PATCH`, with a conventional title and `(#item)`;
  - labels by the issues API (`autopilot`, `risk-high`, `blocked`). This is the first call needing builder-app's
    Issues permission, added to the app and `apps/profitbuild-builder.json` here;
  - a draft for a BLOCKED task;
  - the body is written by the dispatcher from M2's answers: problem first (#0-256), the plan, `Rounds:`,
    `Scope:`, the gate's summary.

  No required status is set with builder-app's credential.

  Backlog edits are not part of the PR: until M5 the owner moves the item to `BACKLOG-DONE.md` in the merge
  follow-up, as for any hand-done item.
- **Where:** `factory`; the app's permission and `apps/*.json` in incident-platform (owner).
- **Check:** an existing PR is reused, not duplicated; the body carries the fields `audit-data.sh` reads.

### M3.4 What a task leaves for the next, before any task holds a credential: #0-285
- **What:** decide and build, as #0-285 states, what keeps a task's leftovers in `factory`'s home, image store,

  Its way is chosen knowing ADR-0063 G1-b phase 2: Sysbox's daemon inside the task container would close this and

- **Where:** VM (`provision.sh`, owner-only), `factory`.

### M3.5 The credential proxy and the transcripts: #0-289
- **Owner's part:** a Console workspace for the factory with a monthly spend limit; its key at
  `/home/dispatcher/.config/factory/anthropic.key` (mode 600).
- **What:**
  - a `node:http` proxy on the containers' host-gateway address. It accepts only the task's token (random per
    task, given as `ANTHROPIC_AUTH_TOKEN`, valid only while the task runs), swaps in the key and streams to
    `api.anthropic.com`;
  - usage counted per task; other Anthropic hosts removed from the task allow-list;
  - #0-274's narrower egress list for `dispatcher` if the proxy needs a rule of its own.
- **Where:** `factory` `dispatcher/src/proxy/`, VM.
- **Check:**
  - a request without the task's token, or after the task ended, is refused;
  - what a token yields is written down: on the shared daemon of M5 (ADR-0063 G1-b phase 1) another task can read
    it through `docker inspect`, so per-task usage is accounting, not a boundary, until phase 2; the spend limit
    caps the total (security review of #0-286);
  - the key never reaches a response or a log;
  - streaming passes unchanged against a fake upstream.
- **Spike first:** Claude Code with `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` needs no login. The cost of a
  run at Console prices is computed from stage 3's baseline.

### M3.6 The adapter's pin: #0-307

  provision.
- **Where:** incident-platform (owner-only `.github/`, `scripts/factory-admin/`).
