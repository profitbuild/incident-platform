## Parts, in order

### M3.1 Checks before a push (ADR-0060 D7), outside the container: #0-305 (with M3.2)
- **What:** these run in the push repository after the task's bundle is read into it, never in the task's clone.
  They build on `factory` PR #20:
  - `withTaskObjects` (`src/git/task-objects.mjs`) is the repository made from the task's bundle, the push's own,
    made fresh for each push from a bundle of the task's lasting repository (#0-302's decisions), never pushed from it;
  - `checkChangedPaths` (`src/product/trusted-paths.mjs`) already refuses a changed `trustedPaths` entry against
    the base's adapter, and is the one function these checks extend.

  The checks:
  - the branch's commits are exactly M2's recorded chain, and each `Factory-Agent` is its call's agent;
  - `merge-base` is the recorded base, and there are no merges;
  - `changed-paths` from `main`, by the dispatcher's own parser of `protectedPaths` (tested against a copy of
    `.ai/rules/protected-paths.md`'s lists, held equal by `check-factory-copies.rb`: #0-278 AC11's second half): an
    Owner-only path stops the task, `needsHuman` sets the owner's label, and no
    `trustedPaths` entry changed;
  - every commit carries the run's trailers.

  For a rebase task (M5, ADR-0063 G1-a) the check is "the base is current `main`" and the push is `--force-with-lease`
  to `factory/**` only. The code path is written here, used from M5.
- **Where:** `factory`. **Check:** each planted case is refused: a merge, a protected path, a missing trailer, a
  base that is not `main` on a rebase.

### M3.4 What a task leaves for the next, before any task holds a credential: #0-285
- **Moved to M5 on 2026-11-22 (ADR-0063 as amended for the new product, R1, R2):** decided as a VM user and rootless
  daemon per slot, each slot wiped after each task; built before M5's two slots. Until then #0-313 AC6's fresh VM
  holds every run with a token. The options below stay a record.
- **Added 2026-11-22 (the review of opencomputer, `opencomputer.md`):** the options compared:
  - nested rootless Podman in the task container, holding no host daemon socket, spiked by gates modelled on
    opencomputer's `sandbox-gates.sh`;
  - Sysbox;
  - a user per slot.

  Choosing the first would amend ADR-0063 G1-b, revisit ADR-0057's Podman alternative and widen ADR-0062 point 6's
  `HostConfig` table; its spike has a gate for what the outer container gives up.

  With the chosen model: limits per task container, and a unix socket per task for the proxy.
- **What:** decide and build, as #0-285 states, what keeps a task's leftovers in `factory`'s home, image store,
  build cache and the Maven cache from the next task's credential (an ADR or an ADR-0062 amendment).

  Its way is chosen knowing ADR-0063 G1-b phase 2: Sysbox's daemon inside the task container would close this and
  the isolation of concurrent tasks at once, so a Sysbox spike may be done here instead of before M12.
- **Taken over from M2.5 (#0-303, the owner's option B, 2026-11-21):** with the daemon's model this step also
  decides and builds the orphans' sweep and the sweep's scope when more than one task can be live (M5's two slots),
  the Maven cache's layout (per slot, or read-only shared with a per-task layer such as Maven 3.9's
  `maven.repo.local.tail`, to check on 3.9.16; today one volume both reads and writes, which a task can poison for
  the next, as #0-285 states), and #0-309: volumes removed without their names in argv (e.g. a `docker volume prune
  --all` filtered by a label the dispatcher sets, to measure on rootless Docker 29.9.3). On a shared daemon a task's
  code chooses names and labels, so what the sweep keeps is held by a count and a deliberate refusal stays possible:
  the way that closes it is a daemon per task.
- **Where:** VM (`provision.sh`, owner-only), `factory`.

### M3.5 The credential proxy and the transcripts: #0-289
- **Moved to M5 with #0-285 on 2026-11-22** (ADR-0063 as amended for the new product, R2).
- **Moved to M2.7 (2026-11-22, ADR-0063 as amended for #0-301):** the proxy's core, the owner's Console workspace and

- **Still M3.5 (now in M5 with #0-285):** #0-274's rule if the proxy needs one; what a token yields within one slot's task

  the transcripts. The plan below is as written before the move;
  its proxy, token and checks are #0-313's now, and so is the task allow-list without Anthropic's hosts (#0-313's
  AC7, 2026-11-22).
- **Owner's part:** a Console workspace for the factory with a monthly spend limit; its key at
  `/home/dispatcher/.config/factory/anthropic.key` (mode 600).
- **What:**
  - a `node:http` proxy on the containers' host-gateway address (since 2026-11-23 a dummy address of its own,
    #0-313's measurement 2). It accepts only the task's token (random per
    task, given as `ANTHROPIC_AUTH_TOKEN`, valid only while the task runs), swaps in the key and streams to

- **Where:** `factory` `dispatcher/src/proxy/`, VM.
- **Check:**

  - what a token yields is written down: on the shared daemon of M5 (ADR-0063 G1-b phase 1) another task can read

    its own task only (ADR-0063 as amended for the new product, R1);

  - streaming passes unchanged against a fake upstream.
- **Spike first:** Claude Code with `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` needs no login. The cost of a
  run at Console prices is computed from stage 3's baseline.
